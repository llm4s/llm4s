# STT Domain Model Expansion - Migration Guide (v0.3.x)

This guide covers breaking and non-breaking changes introduced in the STT domain model expansion (Issue #894).

## Summary of Changes

- ✅ **Non-breaking:** Enhanced `Transcription` with new helper methods
- ✅ **Non-breaking:** Added typed validation factories for `STTOptions` and `WordTimestamp`  
- ✅ **Non-breaking:** Providers now populate `processingTimeMs` metadata
- ⚠️ **Breaking:** `filterByConfidence()` behavior changed to exclude words without confidence scores
- ⚠️ **Breaking:** `totalDuration` now returns maximum endSec (handles unsorted timestamps)

## Key Additions

### 1. New Typed Validation Factories (Non-breaking)

**STTOptions.validate()** - Result-based validation instead of throwing exceptions:

```scala
// New recommended way (Result-based, non-throwing)
STTOptions.validate(
  language = Some("en-US"),
  confidenceThreshold = 0.85
) match {
  case Right(opts) => provider.transcribe(audio, opts)
  case Left(error) => logger.error(error.userFriendly)
}

// Old way still works but not recommended
val opts = STTOptions(
  language = Some("en-US"),
  confidenceThreshold = 0.85
)
```

**WordTimestamp.validate()** - New typed validation method:

```scala
WordTimestamp.validate(
  word = "hello",
  startSec = 0.0,
  endSec = 0.5,
  confidence = Some(0.95)
) match {
  case Right(ts) => /* use timestamp */
  case Left(error) => /* handle */
}
```

### 2. Enhanced Transcription Helper Methods (Non-breaking)

New methods for quality checks and speaker analysis:

```scala
val trans: Transcription = ???

// Confidence analytics
trans.averageConfidence      // Option[Double] - avg of word confidences
trans.minConfidence          // Option[Double] - lowest word confidence
trans.maxConfidence          // Option[Double] - highest word confidence

// Word and speaker analysis
trans.wordCount              // Int - total words in transcription
trans.wordsBySpeaker(1)      // List[String] - words from speaker 1
trans.speakerSegments        // Map[Int, List[(Double, Double)]] - time ranges by speaker

// Quality validation
trans.meetsQualityThreshold(minConfidence = 0.8, minWords = 3)
  // Boolean - true if meets thresholds
```

### 3. Provider Improvements (Non-breaking)

Providers now track and populate additional metadata:

```scala
// Both VoskSpeechToText and WhisperSpeechToText now populate:
val transcription = provider.transcribe(audio, options)

// processingTimeMs is now set by providers
transcription.processingTimeMs  // Some(245) - time in milliseconds

// Word-level confidence extracted when available
transcription.timestamps.map(_.confidence)  // Additional data from providers
```

## Breaking Changes

### 1. Changed: `filterByConfidence()` Behavior

**Before (v0.2.x):**
```scala
val trans = Transcription(
  text = "hello world",
  timestamps = List(
    WordTimestamp("hello", 0.0, 0.5),                    // No confidence
    WordTimestamp("world", 0.6, 1.1, confidence = Some(0.8))
  )
)

val filtered = trans.filterByConfidence(0.5)
// Before: kept words without confidence (assumed passing)
// filtered.timestamps.length == 2  <-- kept both words
```

**After (v0.3.x):**
```scala
// Same input
val filtered = trans.filterByConfidence(0.5)
// After: excludes words without confidence scores
// filtered.timestamps.length == 1  <-- kept only "world" with confidence
```

**Migration:**
- If you need words without confidence scores preserved, filter manually before calling `filterByConfidence()`
- Or adjust your confidence thresholds to 0.0 to match old "any word passes" behavior

### 2. Changed: `totalDuration` Calculation

**Before (v0.2.x):**
```scala
val trans = Transcription(
  text = "test",
  timestamps = List(
    WordTimestamp("end", 2.0, 3.0),  // Last in list
    WordTimestamp("start", 0.0, 1.0) // Second in list
  )
)

trans.totalDuration   // Some(1.0) - took last element's endSec
```

**After (v0.3.x):**
```scala
// Same timestamp list
trans.totalDuration   // Some(3.0) - takes MAX endSec (handles unsorted timestamps)
```

**Migration:**
- If you relied on list order for duration calculations, sort timestamps first
- New behavior is correct for real-world audio where timestamps may not be in order
- To get the last word, use: `trans.timestamps.lastOption.map(_.endSec)`

## Migration Steps for Existing Code

### Step 1: Update Quality Filtering (if affected)

```scala
// Old code that might break:
val filtered = trans.filterByConfidence(0.5)

// New approach - explicitly handle words without confidence
val wordsWithConfidence = trans.timestamps.filter(_.confidence.isDefined)
val filtered = trans.copy(timestamps = 
  wordsWithConfidence.filter(_.confidence.exists(_ >= 0.5))
)
```

### Step 2: Replace Exception-Based Validation

```scala
// Old
try {
  val opts = STTOptions(confidenceThreshold = userInput)
  transcribe(audio, opts)
} catch {
  case e: IllegalArgumentException => /* handle */
}

// New (recommended)
STTOptions.validate(confidenceThreshold = userInput) match {
  case Right(opts) => transcribe(audio, opts)
  case Left(error: STTError) => logger.error(error.userFriendly)
}
```

### Step 3: Leverage New Analytics

```scala
// Built-in quality checks replace manual validation
if (trans.meetsQualityThreshold(minConfidence = 0.8, minWords = 5)) {
  processTranscription(trans)
} else {
  logFailure(trans.averageConfidence, trans.wordCount)
}
```

## FAQ

**Q: Do I need to update all my code immediately?**
A: No. Direct construction and most existing patterns still work. Only `filterByConfidence()` and `totalDuration()` behavior changed. Gradually adopt `validate()` for new code.

**Q: What about existing transcriptions in my database?**
A: No schema changes. The `processingTimeMs` field is optional and will be `None` for transcriptions created with old providers. New transcriptions will have it populated.

**Q: How do I handle words without confidence scores?**
A: The new `filterByConfidence()` excludes them. If you need them, filter before calling `filterByConfidence()`, or use `timestamps.filter(ts => ts.confidence.isDefined && ts.confidence.get >= threshold)`.

**Q: What about speaker diarization?**
A: No API changes. The enhanced `speakerSegments` helper now makes it easier to analyze. Migration is not required, but the new method is more convenient.
