1.0.0 is the stability release. The API is the one [0.7.0](/news/2026/11/25/llm4s-0.7.0/) set the compatibility baseline at, with the few
fixes listed below; what changes is the promise. From this release llm4s follows semantic versioning, and the
frozen modules stay source and binary compatible for the whole of 1.x.

## What 1.0 promises

- **Seven frozen modules:** `llm4s-core`, `llm4s-agent`, `llm4s-openai`, `llm4s-openai-compatible`,
  `llm4s-anthropic`, `llm4s-gemini` and `llm4s-ollama`. A `@Stable` API in them is not renamed, removed or changed
  in a 1.x release. It is removed only in a major release, and only after a release that deprecated it
  ([compatibility policy](/reference/compatibility-policy)). MiMa checks binary compatibility on every pull request
  ([API stability](/reference/api-stability)).
- **What the promise covers:** public types and members, the provider-author SPI, the `LLMError` types and the
  documented configuration keys. The sealed types that may gain a case in a minor release are
  [listed](/reference/compatibility-policy#sealed-types-that-may-gain-a-case): a `match` on one of them needs a
  default case.
- **Inside `llm4s-agent`, a small Stable core:** building and running an agent, its results, handoffs, run ids and
  settings, and attaching guardrails. The graph runtime, checkpointers, events and streaming, middleware, human
  review, delegation, the harness and the run queue are `@Experimental`.
- **Everything else is Beta or Experimental** and may change in a minor release, with a migration note in that
  release's CHANGELOG: RAG and the vector stores, memory, MCP, image and speech, the built-in tools, the
  observability backends, the durable checkpointers, the community providers (Bedrock, Voyage, Jina, Cohere,
  Perplexity, watsonx), the Java, Kotlin and Spring APIs, the effect-system wrappers and the testkits.
  [1.0 Scope](/reference/v1-scope#package-map) has each module's tier, and each public type of a frozen module
  carries `@Stable` or `@Experimental` in the [Scaladoc](/scaladoc/). `llm4s-watsonx` ships unverified against the
  live service.
- **Platform:** Scala 3 only (built with 3.7.1) and JDK 21. Both are raised only in a minor release, never a patch.
- **Support:** 1.0.x gets bug and security fixes. 0.7.x gets critical security fixes until 2027-02-25, and the
  older 0.x lines are end of life ([support policy](/reference/support-policy)).

## What changed since 0.7.0

- An error's `provider` is a `ProviderId`, not a `String`, on the nine errors that name one and on the helpers a
  provider module builds them with (`HttpErrorMapper`, `PartEncoding`, `ensureSuccess`, `mapServiceError`)
  ([migration note](/reference/migration#an-errors-provider-is-a-providerid-2936)). It is the only source break,
  and it changes no binary signature.
- An agent with `withOutput` whose answer is cut off at the output limit ends `AgentStatus.Truncated`, as every other
  agent does, where 0.7.0 returned a `Left`.
- `llm4s-anthropic` no longer sends `max_tokens = 2048` when `maxTokens` is unset: the default follows the model, so
  a call can return, and cost, more than it did. The OpenRouter client likewise fits a Claude model's thinking budget
  under the model's maximum output, where it fitted it under 2048.
- `presencePenalty` and `frequencyPenalty` are sent, or reported on `Completion.adjustments`, on every provider.
  The [migration note](/reference/migration#a-cut-off-answer-ends-truncated-anthropics-max_tokens-default-and-reported-penalties-2933)
  covers these three.
- The Scalafix migration rules are published, as `org.llm4s::llm4s-scalafix`
  ([Scalafix](/reference/scalafix#migration-rules)).

## Upgrading

**From 0.7.0:** with [sbt-scalafix](/reference/scalafix#running-a-migration-rule) and `semanticdbEnabled := true`
in the build, and your code still compiling against 0.7.0, run

```bash
sbt "scalafixAll dependency:Llm4sMigrateFrom_0_7@org.llm4s::llm4s-scalafix:1.0.0"
```

then set the llm4s version to 1.0.0 and compile. The one source break is the `ProviderId`: the rule turns
`RateLimitError("openai")` into `RateLimitError(ProviderId("openai"))` and a read of `error.provider` into
`error.provider.asString`, and the compiler reports what is left, such as a literal provider in a pattern. Code
compiled against 0.7.0 keeps linking, because an opaque type is its `String` in bytecode.
[From 0.7.0 to 1.0.0](/migrations/0x-to-1x#from-070-to-100) lists what the rule rewrites and the behaviour changes
it cannot.

**From an older release:** the same command with the rule for the version you are on, `Llm4sMigrateFrom_0_6` from
0.6.x or `Llm4sMigrateFrom_0_5` from 0.5.x; it rewrites the mechanical part of every break since. Then work down
[Migrating from 0.x to 1.0](/migrations/0x-to-1x) from your release's section: 0.7.0 alone had about a hundred
breaking changes, and the rules report, with a link to its note, what they cannot rewrite. From 0.4.x, start with
[Upgrading from 0.4.1 to 0.5.0](/migrations/0-4-1-to-0-5-0).

## Install

```sbt
libraryDependencies ++= Seq(
  "org.llm4s" %% "llm4s-core"   % "1.0.0",
  "org.llm4s" %% "llm4s-openai" % "1.0.0" // or the provider module you use
)
```

Every artifact, with its tier: [installation guide](/getting-started/installation).
